# 评审对齐、创新点与写作工程

---

## 一、评委在读什么（心智模型）

1. **前 90 秒**：只看**摘要页**。判断：问题是否被真正理解？方法是否成体系？**有没有具体的数值结论**？创新点是否一句话说得清？
2. **接下来 3–5 分钟**：翻**图**。建模思路流程图、核心结果图、灵敏度图。图看不懂 = 论文没做好。
3. **再 5 分钟**：抽查**模型建立**与**结果正确性**。假设是否荒谬、公式是否自洽、数值是否合理、有无检验。
4. **加分时刻**：别人没做的检验（稳健性、误差、对照基线）｜别人没有的视角｜工程化的完整交付（可跑代码、清晰复现说明）。
5. **扣分时刻**：结论没有数值｜图表与正文数字打架｜假设与模型不一致｜灵敏度走过场｜模板腔｜排版事故｜格式违规。

> **一句话原则**：**让评委在不读完的情况下也能确认你是对的。**

## 二、可执行 Rubric（本 skill 提出，非官方评分表）

通过线取 `CONFIG.target.rubric_threshold`（国一目标默认 88），且**无单项低于及格线**。

| 维度 | 分值 | 及格 | 满分证据（必须能指出具体页/图/表） |
|---|---|---|---|
| **摘要页** | 15 | 10 | 问题界定 + 方法链 + **具体数值结论** + 创新点；一页内；可独立阅读 |
| **问题分析与假设** | 10 | 6 | 假设有依据、非空话、与模型一一对应，**每条关键假设被灵敏度回收** |
| **模型建立** | 25 | 16 | 数学表述完整；符号统一；推导逐步可复核、相邻式有衔接；基线与主模型关系清晰；只保留有实测收益的改进；选型有理由 |
| **求解与结果正确性** | 22 | 15 | 算法有理由、参数有来源、结果有数值有图、结果表含单位与基线对照、量纲与数量级正确、有复现命令 |
| **检验与稳健性** | 13 | 8 | 六类均有证据或合理 N/A；适用时做多因素灵敏度；灵敏度含扰动幅度/最大偏差/判定句且关键假设全回收；有基线对照 |
| **写作与图表** | 12 | 8 | 结构清晰、图表专业、正文与图表数字一致、无排版事故 |
| **合规与附录** | 3 | 3 | 格式规范全条通过；附录代码完整可跑；AI 声明合规 |

**创新加权**：未达 `innovation_quota` 时，「模型建立」维度**扣 5 分**（创新性是官方四原则之一，不可缺席）。

### 验收落地

- 把七维逐项写入 `T7_RUBRIC_REVIEW.csv`，列固定为 `dimension,score,max_score,pass_score,evidence,observed,status`；证据必须指向实际页、图、表或检查记录。
- 总分低于 `CONFIG.target.rubric_threshold` 或任一维低于及格线，只能路由 `NEEDS_EXPANSION`，不得把“接近目标”写成 `PASS`。
- 同步维护 `PAPER_COVERAGE_LEDGER.csv`：每问 `interface/definition/algorithm/result/validation/boundary` 六行均可在阅读版 PDF 检索，并映射 C/K/R/P/V/D-id。
- 页数只产生诊断，但诊断必须闭环：阅读版 <14 页或正文汉字 <10000 触发机检深度形态核查（每问字数/编号公式/结果表/摘要密度/评价篇幅，门槛见 §四篇幅预算表），形态项缺失路由 `NEEDS_EXPANSION`，形态项齐全记录 `DEPTH_FORM_CHECKS_PASSED` 机检豁免（warning）后放行；六项证据完整的简洁小问不得仅因页数被否，缺证据也不得靠扩句、贴代码或重复背景补齐；触发与豁免都必须留痕，不允许信号无后续。

### 分级判据

| 论文形态 | 典型归宿 |
|---|---|
| 做完了，模型能跑，结果合理，写作规整 | 省二 / 省一下沿 |
| + 结果经得起检验，图表专业，有灵敏度 | 省一 / 国二 |
| + **清晰创新点** + 基线对照 + 稳健性完整 + 摘要极强 | **国一（金奖）候选** |
| + 机理与数据深度结合、不确定性显式建模、工程化交付完整、结论可操作 | **国一稳态** |

## 三、创新点的合法来源（至少落实 `innovation_quota` 个，并在摘要点名）

1. **模型创新**：提出更强的形式化（把题目重述为随机规划 / 图上流问题 / 最优控制等）。
2. **方法组合创新**：机理+数据、预测+优化闭环、多方法交叉验证，且**能证明组合优于单一**。引入 `references/frontier-cards.md` 的前沿方法属本类，但**必须同时满足其使用纪律第 1–3 条**（基线已跑通、有同口径定量对照表、能做灵敏度并讲清失效条件）；三条缺一即按装饰处理，**不计入 `innovation_quota`**。
3. **视角创新**：发现题面隐含但多数队忽略的因素（异质性、时滞、耦合、边界效应）并量化其影响。
4. **算法/工程创新**：把不可解规模变可解（分解、松弛、剪枝、并行、启发式设计），报告**加速比与解质量**。
5. **验证创新**：设计别人没有的检验（守恒律校验、极端情形推演、独立数据源对照、交叉方法互证）。
6. **交付创新**：把结论转化为**可操作的决策规则/表格/方案卡**——评委非常吃"怎么做"这一套。

7. **证伪式创新**：用可复现的实测结果推翻本题上常被默认成立的做法（如证明 ARIMA 正态区间在本数据实测覆盖率仅 71%、Transformer 长视野不敌单层线性），再给出替代方案与对照表。**负结论也是结论**，但必须有实测数字，不得只做文献转述。

> **最低标准**：能用一句话说出「**没有它会怎样**」。说不出，就不是创新点，是装饰。**用了前沿方法却交不出与经典方法的同口径对照表，评委默认判定为"炫技但没解决问题"，减分大于加分。**

## 四、论文结构骨架（国赛）

```
[承诺书]              ← 纸质版；电子版不含
[编号专用页]          ← 纸质版；电子版不含
[摘要专用页]          ← 电子版第 1 页，页码从此开始；≤1 页；含关键词
1  问题重述           ← 极简：背景 1 段 + 待解决问题分条（禁止大段抄题）
2  问题分析           ← 每问一段 + 总体建模思路图
3  模型假设与符号说明  ← 假设编号 + 依据；符号表（符号/含义/单位）
4  模型建立与求解      ← 每问：模型建立 → 求解算法 → 结果与分析（含图）
5  模型检验与灵敏度分析 ← 独立成章｜嵌入每问小节｜并入评价章三选一（要素见下"检验三种等价合规形态"），不要塞进附录
6  模型评价、改进与推广  ← 优点/缺点/改进/推广，具体不空泛
   AI 工具使用声明     ← 位于参考文献之前；按 2026 版二选一原文
   参考文献            ← 规范著录；2026 版不要求把 AI 工具列为参考文献
   提交版附录          ← 支撑材料文件列表 + 全部可运行源代码；`main.pdf`固定为正文纯净的默认审稿版，提交候选显式命名`*_submission.pdf`
```

**篇幅预算（实测国一区间；正文 ≤30 页）**：问题重述+分析 ≤3｜假设与符号 ≤2｜模型与求解 14–17｜检验与灵敏度 4–5｜评价改进 1｜参考文献 1；合计预留至少 1 页机动。总量与部件按下表 target 列写作，floor 列为机检下限，低于 floor 即 expansion 线索：

| 项 | 写作目标（target） | 机检下限（floor） |
|---|---|---|
| 阅读版正文 | 19–29 页；正文汉字 ≥15000 | 只作触发线：<14 页或 <10000 字 |
| 每问建模求解 | ≥1200 汉字、≥4 编号公式 | ≥800 字、≥1 式 |
| 全文三线表 | ≥4 | ≥3 |
| 全文图 | ≥4 | 不机检 |
| 摘要 | 600–850 字；含单位数值 ≥8 处；逐问各一段；关键词 4–5 | ≥550 字且 ≤1 页；含单位数值 ≥4 处 |
| 模型评价 | 230–450 字；每条优缺点带正文锚点 | ≥200 字 |
| 参考文献 | 3–8 条 | ≥3 条 |

**两列都已机检，但归宿不同**：floor 只在触线后检查，缺项判 `NEEDS_EXPANSION` 阻断交付；target 由 `verify_paper_contract.py` **无条件**检查，未达只出 `TARGET_*` warning 并写入报告的 `target_check` 字段，不阻断。

参考文献另受**默认开启**的可追溯性校验：库路径自锚到脚本旁的 `references/literature-library.md`，无需传参；每条须命中书目库、或带可解析 DOI/ISBN 且在 `--citation-log` 留有实访记录、或属题面官方来源，否则判 `REFERENCE_UNSOURCED` 阻断。未核验时 `reference_check` 各项计数为 `null` 而非 `0`——读到 `null` 表示这道校验根本没跑，不要当成「零条未溯源」。看到「零 error」时 MUST 同时读 `target_check.gaps`——实测出现过 floor 全过、target 8 项中 4 项与逐问 3/5 未达标而报告零 error 的情形，仅看 status 会把「刚过下限」误读成「达到国一水平」。

凭记忆写出的条目与编造在证据上不可区分。

简洁 = 每句有信息，不是每节两句话；低于 floor 的“简洁”是缺证据，不是文风。页数是异常信号，不是质量目标：明显短于该区间时先查证据链是否被压成摘要，明显超出时查重复叙述、无效图表和程序正文；禁止为了“够页数”扩句、贴代码或堆算法简介。异常信号必须闭环：低于触发线（<14 页或 <10000 字）⇒ 机检自动执行深度形态核查；形态项缺失 ⇒ `NEEDS_EXPANSION`，实质扩写后重跑契约；形态项齐全 ⇒ 记录 `DEPTH_FORM_CHECKS_PASSED` 机检豁免（warning）后放行，H-004 仍人工复核表达层；触发与豁免均留痕，不允许信号无后续。模型评价每条优缺点必须带正文锚点（式号/图表号/专有名词）。

**小问完整度（防过度压缩）**：每问正文必须可定位到六项，允许跨节引用但不得只在支撑包：①题意接口（输入、待求对象、前后问接口、物理工件）；②数学定义（变量、单位、目标/方程/约束/统计量）；③求解步骤（数据、参数、算法）；④可复核结果图/表（数值、单位、基线、关键样本）；⑤匹配主要风险的实际验证（含负结果/否决路线）；⑥解释边界（代表什么、不代表什么、依赖与复核触发）。遮住摘要后仍应能复述“为什么建、怎么算、得到什么、凭什么信、哪里不能信”；缺项就补证据，不用代码、支撑清单、引用堆砌或空泛评价补页数。

**每问正文必备清单（六项的成段成表形态）**：接口段 → 编号公式定义（相邻式之间有含操作动词的衔接句——代入/分离变量/积分/求导/联立/展开，禁止“化简得”跳步；新方程带一句可解性论证；参数随式给值带单位；参数来源四句式居一：题给/文献[n]/拟合/估计）→ 算法步骤（Step 编号列表 3–6 步，含终止条件与 ≥1 个候选的选型比较句）→ 结果表五要素（数值/单位/精度/基线对照/关键样本）→ 验证小节 → 边界段。

**哪些形态项已机检、哪些靠人**（避免重复提同一个自动化想法）：

| 形态项 | 状态 |
|---|---|
| 每问汉字数、编号公式数、全文表数、摘要字数与含单位数值、关键词个数、模型评价字数 | `verify_paper_contract.py` 的 floor/target 已机检 |
| 页码自摘要页起连续 | `pagination_check` 已机检 |
| 正文数值 = `RESULTS.md` | `--results-ledger` 已机检 |
| 参考文献可追溯 | 默认开启的 `reference_check` 已机检 |
| 支撑文件列表、源程序嵌入 | 契约已机检（须先建交付物分层，否则整组跳过） |
| **相邻公式衔接句、禁「化简得」跳步** | **刻意不机检**。实测按关键词匹配，「这一结果在建模前并不显然」这类正常论述会被报成跳步；精确判据要求识别「跳步词位于两个编号公式之间的推导链上」，实现复杂且仍会误报。高误报的门禁会训练人忽略警告，比不检更糟 |
| Step 编号列表 3–6 步、结果表五要素、假设↔检验映射 | 靠 reviewer 按本表逐条核。它们的合规形态有多种写法，模式匹配只能查到「有没有出现这个词」，查不到「写得对不对」 |

**检验三种等价合规形态（形态自选，要素缺一即 `NEEDS_EXPANSION`）**：①独立成章；②嵌入每问小节（每问验证小节 + 一处汇总表/图）；③并入模型评价章（实测 4/5 国一无独立章）。任一形态都必须含：误差分析数字句（指标名+数值+阈值判定）；≥2 类灵敏度（特殊情形/参数扰动/放松假设，各含扰动幅度+最大偏差+判定句）；关键假设逐条回收（假设↔检验映射，未回收者写明显式 N/A 理由）；多次运行（随机/仿真类）或同口径基线对照；负结果保留照写。

## 五、摘要写作（权重最高、**最后写**）

**结构模板（以排入摘要专用页后不超过一页为唯一长度门槛）**

```
针对<问题背景>，本文建立了<模型总称>，解决了<n>个问题。

针对问题一，考虑到<关键难点/机理>，本文建立了<模型名>，采用<方法>求解，
得到<具体数值结论：数字+单位>。<一句验证：与X对照误差Y%>。

针对问题二，……（同上结构，突出与问题一的递进关系）

针对问题三，……

本文的创新点在于：(1) <创新点1，说清它解决了什么>；(2) <创新点2>。
模型检验表明<关键结论：参数在依据明确的范围内扰动，最大偏差x%>。

关键词：<4–6 个，含方法名与对象名>
```

**铁律**
1. **必须出现具体数值结论**。"得到最优方案"是废话；"最优投放时刻 t=3.6 s，有效遮蔽时长 12.7 s"才是结论。
2. **禁止模板腔**："本文运用了先进的方法，取得了良好的效果"是评委的负面标记。
3. **不制造悬念**：结论直接给，不要"详见正文"。
4. **陌生人测试**：让没读过正文的人只看摘要，能复述"做了什么、结论是什么"。

## 六、图表规范（评委最先看的东西）

1. **三线表**：只有顶线、表头线、底线，**无竖线**；**表题在表上方**。
2. **图题在图下方**；坐标轴**必须有量名与单位**；图例不遮数据。
3. **必备三类图**：**建模思路流程图**（放"问题分析"，10 秒看懂全局）｜**核心结果图**（每问 ≥1 张，能独立说明结论）｜**灵敏度/稳健性图**（tornado 图、参数扫描曲线、误差带）。
4. 分辨率 ≥300 dpi 或矢量；配色对色盲友好、黑白打印可辨。
5. **禁止**：截图式图表、Excel 默认样式未清理、图片拉伸、大片留白、中文乱码。
6. 图表**必须在正文被引用并解读**（"如图 3 所示，…说明…"）。孤立图表不得分。
7. **正文数字 = 图表数字 = RESULTS.md 数字**，三者不一致即为严重缺陷。

## 七、公式、符号与语言

- 重要公式**居中编号**，正文引用"式(3)"。
- 每个符号**首次出现即定义**并进符号表；**同一符号不得多义**。
- **量纲一致性自查**：等式两端量纲相同——最容易被评委抓到的硬伤。
- 复杂算法给**伪代码**或流程图，标注输入/输出/复杂度。
- 语言客观精确，避免"很好""显著提升"等无量化描述；每个结论句给依据指针（"由表 4 可知""基于式(7)"）。
- **主动控制相似度**：问题重述、模型评价段落必须自己写，禁止套模板。
