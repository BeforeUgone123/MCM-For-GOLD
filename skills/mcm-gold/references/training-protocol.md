# 历年真题训练与防过拟合协议

## 一、目标

用历年真题改进 skill 的通用判断、证据链和生产能力，而不是记住某一题的答案结构。国一是**质量目标**，不是成绩承诺；训练结果须在未参与修改的题目上前向验证。

## 二、数据分层

按题型和年份登记，而不是随机拆文件：

- `discovery`：允许完整调试、查一般方法论文并据此提出 skill 变更。
- `validation`：冻结变更后前向运行；可用于决定是否晋级，但不能边看结果边改同一规则。
- `holdout`：不看公开题解、不针对性改 skill，只在里程碑版本做一次评估；一旦据其结果改规则，该题立即降级为 `validation`，并补充新 holdout。

分层至少覆盖不同数学家族：优化/调度、机理/仿真、预测/统计、评价/决策、几何/物理中的三个。相同附件结构或同一届衍生题不能算独立验证。

## 三、盲测顺序

1. 只读官方题面、附件和规则，冻结输入哈希。
2. 在检索公开题解前完成 T1-T4 基线并冻结 `baseline_snapshot`。
3. 只检索一般领域机理、方法论文、标准和数据说明；不得搜索“年份+题号+答案/代码/论文”。
4. 完成主模型、验证、论文和终检，记录真实墙钟耗时。
5. 演练冻结后才可选读官方讲评或优秀论文；比较“漏了什么/为何漏”，禁止复制其结构和文字。
6. 生成 `REPLAY_REVIEW.md`、skill 变更候选和否决项。

## 四、变更晋级

| 变更类型 | 最低证据 | 晋级条件 |
|---|---|---|
| 事实性不变量/工具陷阱 | 1 次可复现失败 + 修复回归测试 | 问题具有通用机制，如求解器状态误报、模板包结构丢失 |
| 流程/Gate/登记表 | 2 个 discovery + 1 个 validation，至少 2 个题型 | 改善证据完整度或耗时，且不增加不成比例的人机负担 |
| 方法卡/创新套路 | 公平基线、真实数据 PoC、失败边界、至少 1 个负例 | validation 上仍有同预算改进；不得只在命中题上胜出 |
| 写作/图表模板 | 2 个不同内容结构的成稿视觉检查 | 不制造模板腔、旧值残留或信息遮挡 |
| 规则/合规 | 官方原文 + 日期 + 适用届次 | 每届重新核验，不跨届默认沿用 |

单题带来的流程改动先标 `candidate_change`。只有满足晋级条件才写入主干；否则留在训练档案，不把一次偶然成功固化成硬规则。

## 五、核心指标

每次演练至少记录：

- T1 定题/锁定交付物耗时、T4 首次数值耗时、首次可交版本耗时、总墙钟耗时；
- 分问完成率、Gate 真实通过率、P0/P1 缺陷数、返工次数；
- 每个论文数字的运行证据覆盖率、外部事实来源覆盖率、模板/包回读一致率；
- 可复现重跑成功率、求解终止/gap 披露准确率、图表视觉检查通过率；
- 人工强制签署数、被人否决的 AI 建议数、等待时间和不必要打扰数；
- rubric 分项、红队存活率、holdout 相对基线变化。

## 六、归档约定

```text
training/
├─ README.md
├─ BENCHMARK_REGISTRY.csv
├─ SKILL_CHANGE_LOG.csv
├─ research/
├─ benchmarks/<year-problem>/<run-id>/
│  ├─ official/  workspace/  src/  figures/  paper/  deliverables/
│  └─ REPLAY_REVIEW.md
├─ validation/
├─ holdout/
└─ skill-snapshots/<version>/
```

每次修改主 skill 前后各留快照，变更日志写：触发失败、通用假设、影响文件、训练证据、反证/负例、验证题、回滚条件和人确认状态。禁止覆盖既有运行；用新 `run-id` 和 supersession 关联。

## 七、停止过拟合检查

出现以下任一项，停止把经验写入主干：

- 规则包含具体年份、题号、作物名、字段坐标等单题常量，却声称通用；
- 改动只提升同一题的分数或速度，validation 无改善；
- 先进方法依赖题目没有的数据，却靠人工模拟“证明”有效；
- 为通过 Gate 而补造文献、参数、验证或人确认；
- skill 越来越长但冷启动、首次数值或人工审查负担持续变差；
- 公开优秀论文的结构在输出中被机械复现。
